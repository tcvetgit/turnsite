# Сайт «Танкун» — работа вахтой в Москве и Московской области

Готовый статический сайт в этой папке. Стартовая страница — `index.html`; внешний вид — `styles.css`; контакты — `config.js`; интерактивность формы и меню — `app.js`. Серверная функция для Cloudflare Pages находится в `functions/api/lead.js` и отправляет заявки в Telegram и/или на email. Внешних библиотек JavaScript нет. Фото склада в шапке — `img/polza-960.jpg` (сжатая копия исходника `img/polza.png`). Для поисковиков подготовлены `robots.txt` и `sitemap.xml` (в sitemap замените `ВАШ-ДОМЕН` на реальный адрес после публикации).

## 1. Настроить публичные контакты

Откройте `config.js` и заполните нужные поля:

```js
window.SITE_CONFIG = {
  brand: 'ИП Танкун',
  phone: '+79991234567',
  whatsapp: '79991234567',
  telegram: 'rabota_tankun',
  email: 'rabota@example.ru',
  leadEndpoint: '/api/lead'
};
```

- `phone` — номер телефона с кодом страны, для звонка можно использовать `+`.
- `whatsapp` — номер аккаунта WhatsApp только цифрами, включая код страны (пример — `79991234567`, без плюса, пробелов и скобок). Ссылка `wa.me` откроет чат и подставит текст заявки.
- `telegram` — username бота/аккаунта без `@` либо полная публичная ссылка `https://t.me/...`. Укажите контакт, куда соискатель может написать.
- `email` — опубликованный адрес для писем кандидатов.
- `leadEndpoint` — оставьте `/api/lead`, если выкладываете сайт как Cloudflare Pages проект вместе с `functions/`. Для другого хостинга нужен его серверный endpoint с таким же контрактом (POST JSON `{name, phone, job, time, page, consent, website}`) или другой согласованный обработчик.
- `telegram` — в Telegram нельзя открыть чат по номеру телефона, нужен @username. Возьмите его из настроек Telegram (Профиль → Имя пользователя). Пока поле пустое, кнопка Telegram на сайте скрыта и заменяется на форму заявки.
- `max` — ссылка на профиль мессенджера MAX: в приложении откройте профиль → «Поделиться» → скопируйте ссылку вида `https://max.ru/u/...` и вставьте её сюда. Пока поле пустое, кнопка MAX скрыта.

Публичные адреса не являются секретами. Проверьте клики по телефону, WhatsApp, Telegram и email на телефоне и компьютере.

## 2. Получать заявки в Telegram (рекомендуемый быстрый канал)

Серверная функция отправляет уведомления через Telegram Bot API. Токен хранится только в Cloudflare Secrets, на клиент он не попадает.

1. В Telegram откройте официальный `@BotFather`, выполните `/newbot`, задайте имя и username. Сохраните выданный токен в менеджере паролей; никому его не публикуйте.
2. Напишите новому боту `/start`. Бот не может первым начать личный разговор — без этого уведомления не придут.
3. Узнайте свой `chat_id`: откройте `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates` после сообщения боту. В JSON найдите `message.chat.id`. URL содержит секрет: не отправляйте его другим людям и удалите из истории/логов после получения. Альтернатива — настройте группу, добавьте бота и получите ID группы; для супергрупп он обычно начинается с `-100`.
4. В Cloudflare Dashboard создайте Pages project для папки `cmpl` (или для репозитория, где папка `cmpl` указана как **Root directory**). Для обычной раздачи уже собранных файлов задайте build command пустым и output directory `.`. Если проект подключён через Git, убедитесь, что deploy root — именно `cmpl`, чтобы `functions/api/lead.js` обнаруживалась Pages.
5. В Cloudflare: **Workers & Pages → ваш Pages project → Settings → Variables and Secrets → Add**. Создайте два **encrypted secret** с точными именами `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Значения соответственно токен BotFather и chat ID. Перезапустите deploy после изменения настроек.
6. Проверьте сайт реальной тестовой заявкой. Откройте с телефона Telegram-чат владельца бота, сначала нажмите `/start`. Проверьте имя, номер и выбранную вакансию в уведомлении.

Токен нельзя вставлять в `config.js`, HTML/JS, URL сайта, публичный GitHub-репозиторий или присылать соискателю. Если токен случайно раскрыт, отзовите его через BotFather и создайте новый.

## 3. Получать заявки на электронную почту (Resend)

Для писем используется Resend API, вызываемый только с серверной Cloudflare Pages Function.

1. Создайте аккаунт Resend и подтвердите отправляющий домен по инструкциям сервиса (DNS/SPF/DKIM). Использование неподтверждённого домена может блокировать отправку. Адрес `onboarding@resend.dev` подходит лишь для ограниченных тестов и не является адресом для постоянной рассылки.
2. В Resend создайте API key с минимально нужными правами.
3. В настройках Cloudflare Pages добавьте encrypted secrets/variables:
   - `RESEND_API_KEY` — секрет API key;
   - `LEADS_EMAIL` — получатель заявок, например `rabota@example.ru`;
   - `LEADS_FROM` — подтверждённый адрес отправителя, например `Заявки сайта <leads@ваш-домен.ru>`.
4. Повторно разверните Pages project и проверьте тестовую заявку, включая папку «Спам» и логи Resend.

Настройка email независима от Telegram. Функция отправит сообщение во все настроенные каналы; достаточно успешной доставки минимум в один, чтобы вернуть успешный статус форме. Ошибки и статусы доставок проверяйте в Cloudflare Pages Functions logs и логах Resend. Не включайте логирование токенов или полных секретов.

## 4. WhatsApp и Telegram для самого соискателя

Ссылки на WhatsApp и Telegram — это переход в пользовательский чат, а не серверная отправка заявки. WhatsApp не позволяет безопасно и без согласия автоматически отправить от имени кандидата его данные. После заполнения формы кандидат может открыть подготовленный текст и сам нажать «Отправить». Для WhatsApp в настройке `whatsapp` нужен действующий аккаунт, способный принимать обращения. Ссылка на Telegram указывает на username или `t.me` ссылку. Для автоуведомлений владельцу используйте серверную функцию и Telegram bot token/chat ID (раздел 2), а не публичную ссылку на бота.

## 5. Публикация на Cloudflare Pages

1. Для работы формы подключите проект к Git-репозиторию, в котором сайт лежит в `cmpl`, и укажите `cmpl` как deploy root / Root directory. Pages Functions разворачиваются вместе с проектом из Git; простая загрузка статической папки (Direct Upload) не развернёт локальный каталог `functions/`. Для Direct Upload потребуется отдельно развернуть Worker/API endpoint и указать его URL в `leadEndpoint`.
2. Проверьте, что URL `/api/lead` отвечает `405 Method Not Allowed` при GET: это означает, что функция обнаружена (GET для неё не разрешён). Если получается 404, deployment не подхватил каталог `functions` — исправьте deploy root / используйте Git integration с Cloudflare Pages.
3. Заполните контакты в `config.js`, добавьте Telegram и/или email secrets, запустите deploy.
4. Проверьте HTTPS, мобильную версию, телефонный набор, тестовую заявку и получение уведомления. Сотрите тестовые данные, если они больше не нужны.

Сайт можно раздать и с другого статического хостинга, но функция `functions/api/lead.js` рассчитана именно на Cloudflare Pages Functions. Для Netlify/Vercel/обычного хостинга адаптируйте endpoint и его секреты под выбранную платформу. Не вставляйте ключи в код, чтобы «заставить» форму работать.

## Дополнительные возможности интерфейса

- **Плавающая панель (десктоп):** кнопка «Оставить заявку», иконки WhatsApp/Telegram и «Наверх» появляются при прокрутке. Кнопки мессенджеров скрываются автоматически, пока соответствующий контакт не задан в `config.js`.
- **Поле «Удобное время звонка»:** необязательный селектор в форме; значение передаётся на сервер (`time`) и попадает в уведомление Telegram/письмо.
- **Черновик заявки:** имя, телефон, вакансия и время сохраняются в `localStorage` браузера соискателя (ключ `tankun-lead-draft-v1`) и восстанавливаются при возврате на страницу. После успешной отправки черновик удаляется; данные не покидают браузер до отправки формы.
- **Кнопки «Копировать»:** в футере рядом с телефоном и почтой; появляются только для настроенных контактов, показывают «Скопировано».
- **Подсветка активного раздела меню (scrollspy):** на десктопе текущий раздел подчёркивается при прокрутке.
- **Офлайн-предупреждение:** при потере соединения показывается баннер; попытка отправить форму без интернета объясняет ситуацию и заверяет, что черновик сохранён.

## Тестовая проверка

- `index.html` и `privacy.html` открываются по HTTPS; стили и `app.js` загружаются без ошибок.
- На мобильном открывается/закрывается меню, видна нижняя панель контактов, содержимое не обрезается.
- Пустые/неверные имя и телефон показывают ошибку; валидный номер форматируется.
- Тестовая форма возвращает подтверждение только при успешном ответе endpoint; Telegram и/или почта получают ту же заявку.
- WhatsApp открывает правильный чат и содержит составленный текст; Telegram/email открывают правильный контакт.
- Проверьте реквизиты владельца, актуальность вакансий, юридические документы и текст политики до начала рекламы.

## Защита и персональные данные

Заявка включает только имя, телефон и выбранную вакансию. Серверная функция ограничивает длины, проверяет поля, требует подтверждение согласия и ограничивает частоту обращений (не более 5 заявок в минуту с одного IP — базовая защита от спама; облачный лимит действует в рамках одного экземпляра функции и не заменяет полноценный WAF/антиспам на Cloudflare при массовой атаке). Honeypot отбрасывает часть простых ботов. Не собирать паспортные/банковские сведения в эту форму. Ограничьте доступ к чату и почте, настройте сроки хранения и удаляйте данные по запросу. Проверьте соответствие обработки персональных данных применимым требованиям до запуска.

## Внешние ресурсы и шрифты

Шрифты (DM Sans, Manrope) загружаются с `fonts.googleapis.com`/`fonts.gstatic.com` с `display=swap`. Если эти домены недоступны у части пользователей (например, ограничения сети в РФ), сайт автоматически отобразится системным шрифтом — вёрстка не сломается. Для полной автономности скачайте woff2-файлы шрифтов, положите рядом со `styles.css` и замените Google Fonts `<link>` на собственные `@font-face` правила.
